# ADR-001 — 权威模型：Host 权威（非锁步对等）

## 背景

遭遇战为强回合制；需在「纯锁步重放」与「Host 权威」间选择。M02–M05 叙述依赖此决策。

## 决策驱动因素

- 游戏逻辑含协程、动画等待、AI、可能的 `Random`（见 ADR-003）
- 插件以注入为主，难以保证全引擎比特级确定性
- 目标为局域网可信环境（非反作弊）
- 优先可玩性与可纠偏，而非理论最优带宽

## 选项

### 选项 A — 纯锁步对等

各端跑完整模拟；只交换输入；依赖全确定性。

- 优点：无 Host 单点；带宽小  
- 缺点：Unity/AI/协程确定性成本极高；任一端慢或浮点差即分叉且难纠偏  

### 选项 B — Host 权威（采纳）

Host 持有权威 `GS_Battle`；Client 提交 **Intent**；Host **校验并 Apply** 后广播 **Command**（及必要时结果附件）；Client 应用同一逻辑入口；回合边界 **强制 StateHash**，失败则快照覆盖。

- 优点：AI/判胜/RNG 自然单点；与现有 `is_ai` / `SkirmishLogic` 契合；分叉可恢复  
- 缺点：Host 可作弊（LAN 可接受）；Host 掉线需另策（v1 结束会话）  

### 选项 C — 纯状态同步（每步快照）

- 优点：最省事对齐  
- 缺点：包体大、体验差、浪费已有行动 API  

## 决定

**选择 B — Host 权威 + Intent/Command + 回合哈希纠偏。**

补充规则：

1. AI **仅 Host** 决策，并变为可广播的 Command（或 Host-only Apply + 对 Client 的等价 Command）。  
2. 判胜 / `EndGame` **仅 Host** 触发并广播 `MatchEnd`。  
3. Client 本地 UX 可做预测，但 **以 Host 回执为准**；无回执不得推进回合。  
4. 拒绝「无 Host 的纯锁步」作为 v1 目标。

## 后果

- M02/M03/M04/M05 按 B 改写；锁步相关措辞删除。  
- 掉线重连仍 Outside v1（见概况 Out of Scope）。  
- 若未来要做反作弊或无主机赛事，另立 ADR 推翻本决策。
