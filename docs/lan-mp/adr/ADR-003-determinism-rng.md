# ADR-003 — 确定性与随机：Host 结算优先

| 字段 | 值 |
|:---|:---|
| ADR 编号 | ADR-003 |
| 标题 | 联机确定性 / RNG 策略 |
| 状态 | **ACCEPTED（设计基线）** |
| 日期 | 2026-08-29 |
| 决策人 | 设计收敛（人工可 SUPERSEDED 重开） |

---

## 背景

自我审查指出：仅「Command 重放」在存在 `UnityEngine.Random` / AI 随机 / 协程时序差时会静默分叉。需在设计上选定策略，避免 M04 建成后推翻。

## 选项

### 选项 A — 全端确定性锁步（共享 seed，完整重放）

- 优点：带宽小  
- 缺点：需审计并改造一切随机与帧依赖；对注入式模组不现实  

### 选项 B — Host 唯一模拟器 + 结果型同步（采纳）

Host 执行一切改变 `GS_Battle` 的逻辑（含 AI、战斗结算、RNG）。广播的不是「请你本地再 roll 一次」，而是：

1. **Intent**（Client→Host）：玩家意图（单位、行动、目标等）  
2. **Command**（Host→All）：已校验、可在各端调用同一 Apply 入口的指令；若该行动含随机，则附带 **Host 已抽好的结果附件**（命中、伤害、产兵 ID 等）*或* 保证 Apply 在 Client 上走「无再掷骰」路径  
3. **StateHash**（回合边界，见 M05）：不一致则 **StateSnapshot** 覆盖  

开局仍下发 `battleSeed`，供 Host 内 AI/逻辑使用，并便于复现 Host 录像；**不假设** Client 独立重放可比特一致。

- 优点：与 ADR-001 一致；不依赖全引擎确定性；分叉可检测可恢复  
- 缺点：协议需能表达结果附件；初期可对「已验证无 RNG 的动作」省略附件，遇 hash 失败再收紧  

### 选项 C — 逐步纯快照

每指令后全量 `Save_General`。正确但重；仅作 M05 纠偏手段，不作主路径。

## 决定

**选择 B，C 仅作纠偏后备。**

落地规则：

| 规则 | 说明 |
|:---|:---|
| R1 | 一切 RNG 只在 Host 消费 |
| R2 | Client 禁止在联机局调用会导致逻辑分叉的本地结算捷径 |
| R3 | v1 允许「先 Command 重放 + EndTurn Hash」；一旦出现系统性分叉，对该类 `ActionCate` 升级为结果附件，而不改权威模型 |
| R4 | 动画/镜头/音效允许分叉；不得进入 StateHash 集合 |
| R5 | `battleSeed` 写入 `LobbyStart`，Host 日志永久保留 |

## 后果

- M04 主路径改为 Intent→Host Apply→Command（± 结果附件）  
- M05 从「可选打磨」提升为 **MVP 必开严格 Hash（开发期）**；发行可配置快照纠偏  
- 不把「全游戏确定性改造」列入 Scope
