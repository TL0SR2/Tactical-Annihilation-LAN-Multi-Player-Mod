## 背景

需在不重打包游戏的前提下加载联机插件并挂钩 `Assembly-CSharp`。游戏为 **Unity Mono**（存在 `MonoBleedingEdge`）。

## 选项

### 选项 A — BepInEx + Harmony（采纳）

- 优点：模组生态成熟；补丁可审可撤；与 Mono 匹配案例多  
- 缺点：依赖门禁版本与游戏更新；需维护 Doorstop 配置  

### 选项 B — 自写原生门面 + 手工入口

- 优点：无第三方  
- 缺点：重复造轮子；挂钩与生命周期成本高  

### 选项 C — 直接改 `Assembly-CSharp.dll`

- 优点：短平快  
- 缺点：Steam 校验/更新灾难；不可作为工程默认  

## 决定

**选择 A。** 版本在实现 M06 时锁定具体 BepInEx 主版本（5 或 6），以「能稳定注入本游戏 Mono」实测为准；文档不预绑未验证的次版本号。

约束（写入 M06）：

1. **禁止**默认发行「改 DLL」方案。  
2. 挂钩点白名单制；未过审补丁点不得合并。  
3. **优先钩同步方法**（如 `MannualEndTurn`、Command 调度入口）；对 `IEnumerator` 主体避免直接改写迭代器，必要时只钩 `StartCoroutine` 调度或同步包装方法。  
4. 插件与文档/源码放在 **独立仓库或并列目录**，不依赖 Steam 安装目录作为唯一真相源。  
5. 启动日志打印：插件版本、`Assembly-CSharp` 文件哈希。

## 后果

- M06 按 A 实施；工程模板在 M06 APPROVED 后创建。  
- 游戏大版本更新 → 重新验证挂钩点并 bump 插件兼容表。
